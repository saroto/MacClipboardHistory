# MacOsClipBoard

A macOS clipboard history manager modeled on the Windows `Win+V` panel: a global
hotkey summons a floating panel over whatever app is frontmost, you pick a past
clip with the keyboard, the panel dismisses and the clip is pasted into the app
you came from.

Status: **feature-complete for v1.** Background agent, pasteboard capture with
dedupe, retention/expiry, menu bar popover, global hotkey (⌘⇧V by default), and a
floating panel that pastes into the app you came from. Remaining work is polish:
richer clip types, a proper key recorder, and an app icon.

## Decisions already made

| Decision | Choice | Consequence |
| --- | --- | --- |
| Distribution | Direct / local, **not** Mac App Store | `ENABLE_APP_SANDBOX` is **off** (done) |
| Persistence | **SwiftData** | `Persistence.swift` + `.xcdatamodeld` removed (done) |
| v1 clip types | **Plain text only** | Rich text, images and file URLs are explicitly out of scope for v1 |
| Deployment target | macOS 26.5 | No back-compat guards. Use current APIs freely. |

Do not re-litigate these without asking. In particular, do not "helpfully" restore
the sandbox — auto-paste depends on it being off.

## Architecture

The app is a **menu bar agent** (`LSUIElement`), not a windowed app. There is no
main window and no Dock icon.

```
MacOsClipBoardApp (@main)
├─ MenuBarExtra          → status item: recent clips, Settings, Quit
├─ Settings scene        → hotkey, history limit, launch at login
└─ AppDelegate (NSApplicationDelegateAdaptor)
   ├─ ClipboardMonitor   → polls NSPasteboard, writes Clip models
   ├─ HotKeyManager      → registers the global summon shortcut
   └─ PanelController    → owns the floating NSPanel + focus restore + paste
```

Files under `MacOsClipBoard/` (flat is fine at this size) — ✓ exists, ○ to write:

- ✓ `MacOsClipBoardApp.swift` — `@main`, scenes, model container
- ✓ `Models/Clip.swift` — the SwiftData `@Model` + preview helpers
- ✓ `Models/AppModelContainer.swift` — container and explicit store URL
- ✓ `Models/ClipStore.swift` — every write goes through here (dedupe, prune)
- ✓ `UI/ClipListView.swift` — SwiftUI content of the panel
- ✓ `AppDelegate.swift` — owns the monitor and sweeper, starts them at launch
- ✓ `Services/ClipboardMonitor.swift` — the poll loop
- ✓ `Services/RetentionSweeper.swift` — slow timer enforcing expiry
- ✓ `Services/AppSettings.swift` — retention window + history cap
- ✓ `UI/SettingsView.swift`
- ✓ `Services/HotKeyManager.swift` — Carbon global shortcut
- ✓ `Services/PasteService.swift` — Accessibility check + synthetic Cmd+V
- ✓ `UI/PanelController.swift` — the `NSPanel` host + focus/paste sequence

**Adding files is easy here.** The project uses Xcode 16+ file-system-synchronized
groups (`objectVersion = 77`), so any `.swift` file written into `MacOsClipBoard/`
is compiled into the target automatically. Never hand-edit `project.pbxproj` to
add sources.

## The four hard parts

Everything else is a list view. These are where the real work is — read this
section before writing code that touches them.

### 1. Detecting a new clip — and keeping it free

macOS has **no** pasteboard-change notification. The only supported approach is
polling `NSPasteboard.general.changeCount` on a timer (~0.2–0.5 s); when the count
differs from the last seen value, read the contents.

This app runs for the whole login session, so the poll must stay near-free. Three
things keep it there, and all three must survive future edits:

1. `changeCount` is a cheap IPC read. The *contents* are only read on the rare tick
   where the count actually moved.
2. **Timer tolerance.** `ClipboardMonitor.pollTolerance` lets macOS slide each tick
   to coalesce it with other wakeups instead of waking an idle CPU on our schedule.
   This is the single biggest battery factor; do not drop it.
3. Polling stops entirely between `NSWorkspace.willSleepNotification` and
   `didWakeNotification`.

Measured on this machine: **~0.05 s of CPU over 80 s idle (≈0.06%), 63 MB RSS.**
If a change ever pushes idle CPU meaningfully above that, it is a regression.

- Ignore clips carrying the `org.nspasteboard.ConcealedType`,
  `TransientType`, or `AutoGeneratedType` markers — that is the community
  convention password managers use to say "do not record this". Honoring it is a
  correctness requirement, not a nicety.
- Skip the write we performed ourselves: record the `changeCount` after this app
  writes to the pasteboard and ignore that generation, or the app will re-capture
  its own paste as a new clip.
- Attribute the clip to `NSWorkspace.shared.frontmostApplication?.bundleIdentifier`
  at capture time so the UI can show a source app.

### 2. The floating panel

A normal `Window`/`WindowGroup` steals focus and will not appear over full-screen
apps. Use an `NSPanel` hosting an `NSHostingView`:

- `styleMask` includes `.nonactivatingPanel` so summoning it does not deactivate
  the app underneath.
- Subclass and override `canBecomeKey` to return `true` — a nonactivating panel
  will not receive keystrokes otherwise, which is the single most common way this
  gets stuck.
- `level = .floating`, `collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]`.
- Dismiss on Escape (`cancelOperation`), on selection, and on resigning key.
- `.nonactivatingPanel` alone does not reliably give an accessory app the keyboard,
  so `show()` also calls `NSApp.activate(ignoringOtherApps:)`. That is safe *only*
  because `previousApp` was captured first and focus is handed back on every exit
  path — if you add a new dismissal route, restore focus there too.
- Arrow keys must be handled on the container (`.onKeyPress`), not left to the
  `List`: the search field holds focus so the list never sees them.

### 3. Restoring focus and pasting

Order matters and is easy to get wrong:

1. **Before** showing the panel, capture `NSWorkspace.shared.frontmostApplication`.
2. On selection: write the clip to `NSPasteboard.general`, close the panel.
3. Reactivate the captured `NSRunningApplication`.
4. Only then post the synthetic Cmd+V (`CGEvent` key down/up, keycode `9`,
   `.maskCommand`, posted to `.cgSessionEventTap`), after a small delay so the
   target app is actually key.

Posting the paste before the target app regains focus silently does nothing —
the usual symptom of "the hotkey works but nothing pastes".

### 4. Permissions and code signing

Synthetic paste requires **Accessibility** (Privacy & Security → Accessibility).
Gate it on `AXIsProcessTrustedWithOptions` and degrade gracefully: if permission
is absent, still put the clip on the pasteboard and let the user press Cmd+V.

The Accessibility grant is bound to the app's **code signature**. If the signing
identity changes between builds, macOS treats it as a different app and the user
must re-grant — and stale entries pile up in the list. Keep signing on the
existing team (`DEVELOPMENT_TEAM = LV6S289L52`) rather than switching to ad-hoc.

For the global hotkey, `HotKeyManager` uses Carbon `RegisterEventHotKey` — it needs
no permission at all. Only reach for a `CGEventTap` if the hotkey needs to be
user-remappable to something Carbon cannot express; a tap requires Accessibility
and puts this process in the path of every keystroke on the machine.

`RegisterEventHotKey` fails when another app already owns the combination, so
`register` returns a `Bool` — surface that rather than silently ending up with a
shortcut that does nothing. Settings offers four presets instead of a key recorder.

Auto-paste degrades rather than failing: with Accessibility denied, or the setting
off, choosing a clip still copies it and the user presses ⌘V. Keep that fallback.

## Data model sketch

```swift
@Model final class Clip {
    var content: String
    var contentHash: String       // for dedupe
    var createdAt: Date
    var lastUsedAt: Date
    var isPinned: Bool
    var sourceBundleID: String?
}
```

- **Dedupe on hash.** A repeat of an existing clip should move that row to the top
  (bump `lastUsedAt`), never insert a duplicate.
- **Cap the history** (default ~500 unpinned clips) and prune oldest-first on
  insert. Pinned clips are exempt from pruning.
- Clip text can be large — truncate for display, keep the original for pasting.
- **Never use SwiftData's default store location.** Unsandboxed, it writes a file
  named `default.store` into the *shared* `~/Library/Application Support/`, where
  other apps have already put their own. This machine has one there dating from
  2025 that belongs to a different app. `AppModelContainer.storeURL` pins ours to
  `~/Library/Application Support/MacOsClipBoard/ClipHistory.store` — keep it that way.
- **Commit before pruning.** `fetchOffset`/`fetchLimit` apply to *persisted rows
  only*; SwiftData merges unsaved in-memory inserts into the result **after** the
  offset. Pruning with an uncommitted insert in the context therefore deletes the
  clip just recorded — insert + delete in one transaction, which commits as a
  silent no-op (`save()` returns success and nothing lands on disk). `ClipStore.record`
  saves before calling `prune()` for exactly this reason. Do not reorder it.
- `Bool` is not `Comparable`, so `isPinned` cannot be a `SortDescriptor`. `@Query`
  sorts by `lastUsedAt` only; pinned-first ordering is a stable partition done in
  `ClipListView.visibleClips`.


Because this is a background agent, a stale copy can keep running and hold the
hotkey after a rebuild. Kill it before relaunching:

```bash
pkill -x MacOsClipBoard
```

## Retention — history must not grow forever

Three independent limits, all enforced in `ClipStore`:

| Limit | Where | Default |
| --- | --- | --- |
| Age | `sweepExpired(retention:)`, run by `RetentionSweeper` | 1 week |
| Count | `prune()`, run on every capture | 500 clips |
| Per-clip size | `ClipboardMonitor.maxClipCharacters` | 256k characters |

- **Pinned clips are exempt from both age and count limits.** Pinning is the user
  saying "keep this regardless"; a sweep that drops a pinned clip is a bug.
- The sweep is a **batch delete** (`context.delete(model:where:)`), which SwiftData
  pushes down to a single SQL statement instead of faulting every expired clip into
  memory. Keep it that way — it is what makes expiry cost independent of history size.
- Expiry is not time-critical, so `RetentionSweeper` runs every 10 minutes with a
  60 s tolerance, plus once at launch to catch up on whatever expired while the app
  was not running.
- Both are user-visible in Settings, along with a manual sweep and a
  "clear unpinned history" button.

## Debugging this app

It is a background agent with no Dock icon, which makes two failure modes very easy
to mistake for code bugs. Both cost real time during development:

- **A stale instance blocks the new one.** `pkill -x MacOsClipBoard` does not
  reliably kill a wedged agent; `open` then silently re-activates the *old* process
  and fails with `_LSOpenURLsWithCompletionHandler() failed with error -1712`. You
  end up testing a corpse. Always `pkill -9 -x MacOsClipBoard`, confirm with
  `pgrep -x MacOsClipBoard`, and check you have exactly one instance.
- **Console noise that is not yours.** Running under Xcode produces
  `fopen failed for data file: errno = 2` (CoreGraphics/Metal shader cache, created
  on first use) and `Unable to obtain a task name port right for pid <n>` where the
  pid is WindowServer (SIP refusing a task port, by design). The app itself writes
  nothing to stdout/stderr — verified by running the binary directly — so treat
  both as environment noise, not symptoms.
- **`log show` can come back empty.** A build launched with Xcode's debug dylibs
  loads `libLogRedirect.dylib`, which routes `os_log` output to an Xcode console
  that is not attached. Absence of log lines proves nothing. When a run has to be
  observed from the command line, write markers to a file instead.

- **The global hotkey cannot be tested from a script.** Synthesizing ⌘⇧V via
  `osascript`/System Events needs Accessibility for the *terminal*, and without it
  the call hangs and dies with AppleEvent timeout −1712. Verify the panel by
  driving `PanelController` directly (a temporary `DistributedNotificationCenter`
  observer works well and is easy to strip), and confirm it is on screen with
  `CGWindowListCopyWindowInfo` — a floating panel shows at `layer=3`.
- Focus and activation cannot be verified while the screen is locked: `lsappinfo
  front` reports `loginwindow` and every activation result is meaningless. Check
  that first before debugging a focus problem.

To inspect the store directly (the app holds it open in WAL mode, so copy the
sidecars too, or the rows will look like they are missing):

```bash
sqlite3 ~/Library/Application\ Support/MacOsClipBoard/ClipHistory.store "SELECT ZCONTENT FROM ZCLIP ORDER BY ZLASTUSEDAT DESC;"
```

`Z_PRIMARYKEY.Z_MAX` is the highest primary key ever handed out for an entity. If
it is `0`, no row was *ever* inserted — which distinguishes "rows were deleted"
from "the write never happened".

## Conventions

- Swift 6 concurrency. `ClipboardMonitor`, `PanelController` and all SwiftData
  access are `@MainActor`.
- `SWIFT_VERSION` is `6.0`, and the project sets
  **`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`** — every declaration is implicitly
  main-actor isolated unless marked otherwise. Two consequences that already bit:
  a C function pointer (the Carbon hotkey callback) cannot be formed from an
  isolated function, so it must be explicitly `nonisolated`; and imported C globals
  like `kAXTrustedCheckOptionPrompt` are rejected as shared mutable state, so use
  the underlying string value instead.
- No `fatalError` in shipped paths. A clipboard manager that crashes on a save
  error is worse than one that drops a clip — `ClipStore.save()` logs and
  continues, and `AppModelContainer` falls back to an in-memory store rather than
  refusing to launch. Preserve that posture.
- No third-party dependencies without asking. Everything above is achievable with
  AppKit + SwiftUI + SwiftData.
- Prefer AppKit directly where SwiftUI has no equivalent (panels, event taps,
  status item behavior). Do not fight SwiftUI to avoid an `NSViewRepresentable`.

## Privacy

This app records everything the user copies, including things typed into password
fields of apps that do not set the concealed-type marker. Never add telemetry,
network calls, or cloud sync without an explicit request. Storage stays local.
